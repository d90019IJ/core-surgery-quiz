# 核心外科講堂隨堂測驗

- 學員：https://d90019ij.github.io/core-surgery-quiz/
- 講師：https://d90019ij.github.io/core-surgery-quiz/admin.html

## 課程流程

每場有指定日期，台灣時間 18:30 開放，19:30 同時截止考試及必填問卷。日期可在講師後台設定，未設定日期時不開放。暫停／恢復收件仍受時間限制，不會讓過期場次重新開放。

本場僅限 B 組名單中的學員，姓名與學號經伺服器核對相符才可進入考試或問卷。名單保存於受保護資料庫，講師可在後台查看；不公開於 GitHub。空名單的場次不允許進入。

學員填寫姓名及本人學號，完成五題單選題、交卷後填寫五項必填課後問卷。只有兩者皆成功送出，才算完成課程。交卷不顯示分數、正確答案或解析。問卷送出後顯示「問卷已送出」與課程完成確認。

- 同一場次同一學號只儲存第一份成功交卷，禁止覆寫或重考。
- 自填姓名與學號沒有身分驗證，無法防止冒用其他學號；此模式由講師選定。
- 學號標準化全形字元、前後空白與英文大小寫；限 1–32 碼英數字及連字號。
- 只交考卷的學員可在截止前再次填寫身分資料，直接進入問卷，不會重新考試。未送出的問卷選項不會自動儲存，需要重新填選。
- 19:30 整及之後不接受任何新的考卷或問卷，已開著的頁面也不能繞過。截止判斷由資料庫實際時鐘執行，不依賴手機時間或交易開始時間。
- 網路中斷可重新查詢完成狀態或重試，已成功的交卷與問卷都不會被重複計入。
- 每題等分，五題共 100 分，只由伺服器評分、講師查看。

## 講師後台

登入管理碼沿用原本另外交付的 256-bit 隨機碼，不寫入此儲存庫或瀏覽器儲存空間。可設定日期、暫停／恢復收件、查看交卷人數／課程完成人數／問卷未完成人數，匯出成績及完成狀態 CSV。

問卷統計在截止後提供，顯示各題各選項的人數並可另行匯出 CSV；不提供個人問卷答案。收件期間不提供即時問卷分布，以減少由數字變化推測個人回答的機會。

## 問卷資料分離

學員交卷表只新增布林欄位 survey_complete，沒有問卷答案、問卷編號或完成時間。

core_quiz_survey_counts 只保存場次、題目、選項、人數。沒有姓名、學號、個別問卷紀錄、共用連結編號或時間戳。不同題目的回答不保存為同一份問卷組合。伺服器在單一交易內驗證已交卷、尚未完成、仍在開放時間，再增加五個匿名選項計數並標記學員完成。輸入錯誤或逾時會全部回復；同一學員的並行重送以資料庫鎖序列化。

API 不記錄問卷請求內容。這是應用程式層面的答案與身分分離，不承諾對資料庫營運者或只有極少數回覆的情境提供不可推測的絕對匿名。

問卷內容依提供的滿意度圖片建立：教學表達、教材實用性、教材難易度、時間掌控、考試方式。難易度採「非常簡單／簡單／適中／困難／非常困難」；其他四項採五級滿意度。

## 架構與保護

web/ 透過 GitHub Pages 的 gh-pages 分支發布；server/ 是 Supabase Edge Function。實際考題、正確答案、管理碼、成績及原始講義不放入公開儲存庫。private/、tmp/、環境檔已排除 Git。

所有資料表啟用 RLS 並撤銷匿名及一般登入角色存取。伺服器角色僅留在 Edge Function 環境。資料庫函式使用 SECURITY INVOKER，撤銷 PUBLIC/anon/authenticated 的執行權，只授予 service_role。資料表未配置允許 client 的 RLS policy 是刻意預設拒絕；安全檢查會因此出現 informational 提示，並非缺少權限保護。

考卷寫入觸發器在實際 INSERT 再檢查 clock_timestamp()，因此舊版本 API 也不能在截止後寫入。問卷函式在鎖定學員紀錄之後檢查時間，累加統計後再檢查一次，逾時則回復交易。

## 初始化及升級

新專案依序執行 database/schema.sql、database/schedule-survey.sql 及 database/roster.sql。既有專案只執行尚未套用的遷移一次。名單由私有來源匯入 core_quiz_roster，不能把實際姓名學號寫入公開 SQL。既有交卷保留，問卷完成狀態初始為 false。

部署 server/index.ts、application.mjs、supabase-repository.mjs、deno.json。更新既有 Edge Function 時明確指定 import_map_path 為 deno.json。學生依需求採自填身分，因此 verify_jwt=false；講師操作仍由函式內專用管理碼驗證。

在 web/config.js 設定公開 API 網址及場次編號。只將 web/ 子目錄發布到 gh-pages 根目錄，不可發布 private/ 或整個工作目錄。

## 開發與驗證

Node.js 22.13 以上，無第三方執行相依。執行 npm test 及 npm run check。

本機預覽執行 npm start，需要獨立提供 private/seed.json。本機 SQLite 與正式成績分離。PREVIEW_CLOCK 環境變數只影響本機預覽，可用於模擬 18:30–19:30；正式後端沒有模擬時間功能。

tests/api.test.mjs 驗證精確開始／截止邊界、日期、權限、重送、問卷完整性、身份分離及恢復。database/verify-schedule-survey.sql 以可回復的合成資料驗證真正 PostgreSQL 的交易、觸發器、截止與權限。瀏覽器另外驗證手機、跨瀏覽器補填、日期設定及匿名 CSV。

## 下一場考試

新增獨立的 core_quiz_exams 場次 ID，並匯入該場的應考名單，使用 ?exam=場次ID 的學員及講師網址，舊成績保留。更改既有日期不會重置學號作答機會；下一次考試應建立新場次。不要修改已收卷場次的題目或答案。

考試題目原文及答案依講師提供的五張截圖輸入，未自行改判。2024 年講義僅供課程參考，未公開發布。

講師可在「考試名單」補登本班同學的姓名與學號；重複學號會拒絕新增，不會覆寫現有名單。套用 database/roster-add.sql 授予伺服器新增名單權限，匿名與一般登入角色仍無權存取。
